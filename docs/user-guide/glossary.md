| ----------- | ------------------------------------ |

**Capacity domain**
A type of hospital resource whose volume is required to be estiamted from 
predicted activity data, for example critical care beds.

**Datetime** 
The numeric date and time 'stamp' a demand model scenario is given 
when run. 
It can be used as an additional identifier when multiple model scenarios share 
a name. 

**Functional area** 
A resource and the context in which it is being used (e.g. 
BEDS_DAYCASE_RECOVERY is hospital beds that are being used for the recovery 
period following daycase procedures)

**Occupancy rate**
The proportion of units of a resource type (typically beds) that are in use at 
a point in time. For example, if 8 out of 10 beds are in use in a ward, the
occupancy rate is 80%.

**Operational constraint** 
The method by which the resource usage is monitored or measured. 
For example, occupancy rate, utilisation rate, throughput.

**p10, p90** 
The values from a distribution of results whereby 10 percent of
results were below the value ('p10') or 10 percent were above the value (p90).

**Probabilistic** 
A type of model that predicts probabilities of outcomes, 
rather than specific certainties. 
The OpenPlan Demand Model is probabilistic in that, given the exact same inputs,
you would not expect the exact same results.

**Utilisation rate**
Use of a resource relative to its maximum capacity. 
For example the proportion of operational time that a theatre is in use per day.

**Workload object** 
The volume of a type of hospital activity. For example
'ward bed days'.
